# 代码仓阅读口径

当输入是 GitHub 仓或本地代码目录时，先按 Repo Explainer 的思路读取实际源文件，而非把 README 当作行为证据。

1. 固定版本：记录 URL、分支、commit 与读取日期。
   再次拆解先核对已有底稿的版本与读取范围。同版本且相关文件未改可复用已验证事实；不能把上次的报告文字当源码。版本、文件内容或范围不同，则读取差异、缺口和受影响依赖；远端不可达时标注快照日期。用户业务现状独立复核。
2. 识别形态：应用、库、CLI、MCP、Skill 集合或纯文档仓。
3. 找真实入口、配置、关键模块、依赖和外部调用；每个非显然结论带 `路径:行号`。
4. 对纯 Skill 集合，分析 Skill 的触发条件、输入、判断、输出和限制；不要伪造函数调用关系。
5. 输出同时面向小白解释技术术语，并如实说明无法从源码证明的部分。

不运行目标代码。若用户只需要代码阅读，不需要“化为己用”，改用 `$repo-explainer` 即可。
